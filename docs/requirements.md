# Requirements Specification

## 1. 문서 목적

이 문서는 Semiconductor Document RAG AI Agent의 제품 범위와 검증 가능한 요구사항을 정의한다. 구현 세부사항은 설계 문서와 ADR에서 다루며, 모든 기능은 이 문서의 요구사항 ID와 연결한다.

## 2. 제품 목표

반도체 PDF, 공정 문서, 장비 매뉴얼, 논문을 검색하고 여러 문서의 내용을 비교·분석하여 **문서명과 페이지 단위 근거를 포함한 답변**을 제공한다. 근거가 부족하거나 문서가 서로 충돌하면 이를 명확하게 알리고 답변을 보류하거나 추가 검색을 수행한다.

### 2.1 성공의 정의

- 사용자가 답변의 근거를 원문 PDF 페이지에서 확인할 수 있다.
- 정확한 약어·장비 코드·수치 검색과 의미 기반 검색을 함께 지원한다.
- 다중 문서 비교 시 각 문서의 주장과 조건이 섞이지 않는다.
- 검색 실패와 근거 부족을 정상적인 결과로 다룬다.
- 검색, 인용, Agent 행동을 자동 평가하고 재현할 수 있다.

## 3. 사용자

| Persona | 주요 요구 | 기본 설명 수준 |
| --- | --- | --- |
| 반도체 입문자 | 용어 설명과 핵심 개념 이해 | 쉬운 용어, 약어 풀이 포함 |
| 취업 준비생 | 공정·장비 지식 비교와 면접 준비 | 개념과 실무 연결 |
| 공정·장비 엔지니어 | 매뉴얼 조건, 알람, 조치 절차 검색 | 원문 표현과 수치 보존 |
| 연구자 | 논문 간 방법·조건·결과 비교 | 세부 조건과 한계 포함 |

설명 수준은 답변의 표현만 바꾸며, 검색 근거와 인용 기준은 동일하게 유지한다.

## 4. 범위

### 4.1 MVP 포함 범위

- 텍스트 PDF 및 대표 스캔 PDF 처리
- 한국어, 영어, 한영 혼합 질문
- 본문, 제목, 목록, 표의 페이지 기반 검색
- Dense Search와 BM25를 결합한 Hybrid Search
- Reranking
- 단일 문서 질의, 다중 문서 비교, 표 기반 질의
- 문서명·페이지·근거 발췌를 포함한 답변
- 근거 부족 및 충돌 시 답변 보류
- LangGraph 기반 재검색 및 MCP 도구 호출
- 오프라인 평가와 Streamlit 데모

### 4.2 MVP 제외 범위

- 모든 PDF 레이아웃에 대한 완전한 파싱 보장
- 사내 문서 권한 관리와 기업용 SSO
- 실시간 공동 편집과 문서 승인 워크플로
- 모델 Fine-tuning
- 대규모 멀티테넌트 운영
- 이미지·도면 자체의 정밀 시각 추론
- 제조 데이터 분석의 전체 제품화

### 4.3 후속 확장

- SQL·Pandas 기반 제조 데이터 분석 도구
- 이미지·도면·그래프 멀티모달 검색
- 문서 변경 감지와 증분 재색인
- 조직·프로젝트별 접근 제어

## 5. 핵심 사용자 시나리오

### US-001 단일 문서 근거 검색

사용자는 장비 매뉴얼에서 알람 원인과 조치 절차를 질문한다. 시스템은 관련 페이지를 찾고 문서명, 페이지, 근거 문장을 포함해 답변한다.

### US-002 다중 문서 비교

사용자는 서로 다른 공정 문서에서 온도, 압력, 재료 조건을 비교한다. 시스템은 문서별 조건을 분리하고 각 항목에 개별 인용을 연결한다.

### US-003 표 검색

사용자는 표에서 특정 recipe나 최고 선택비 조건을 찾는다. 시스템은 표의 행·열 관계를 유지해 값을 반환하고 원문 페이지를 제시한다.

### US-004 용어 수준 조절

사용자는 입문자 또는 실무자 설명 수준을 선택한다. 시스템은 동일 근거를 유지하면서 설명 깊이와 용어 풀이를 조절한다.

### US-005 답변 보류

질문의 답이 등록된 문서에 없으면 시스템은 추측하지 않고 근거 부족 사유와 추가로 필요한 문서를 안내한다.

## 6. 기능 요구사항

### 6.1 Document Ingestion

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-ING-001 | 시스템은 PDF를 업로드하고 안정적인 `document_id`와 `version_id`를 생성해야 한다. | Must |
| FR-ING-002 | 시스템은 PDF의 물리 페이지 번호를 1-based 값으로 보존해야 한다. | Must |
| FR-ING-003 | 시스템은 제목, 본문, 목록, 표를 구분 가능한 Element로 저장해야 한다. | Must |
| FR-ING-004 | 텍스트가 부족한 페이지는 OCR 대상으로 식별해야 한다. | Must |
| FR-ING-005 | 모든 Chunk는 원본 Document, Page, Element로 역추적되어야 한다. | Must |
| FR-ING-006 | 동일 파일과 동일 파서 설정의 재수집은 중복 인덱스를 만들지 않아야 한다. | Must |
| FR-ING-007 | 파싱 실패 페이지와 원인을 기록하고 나머지 페이지 처리를 계속해야 한다. | Should |
| FR-ING-008 | 문서 삭제 시 관련 메타데이터와 검색 인덱스를 일관되게 제거해야 한다. | Should |

### 6.2 Retrieval

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-RET-001 | 시스템은 Dense Vector Search를 제공해야 한다. | Must |
| FR-RET-002 | 시스템은 BM25 Keyword Search를 제공해야 한다. | Must |
| FR-RET-003 | 두 검색 결과를 문서·페이지 중복을 고려해 융합해야 한다. | Must |
| FR-RET-004 | 최종 후보를 Cross-Encoder로 재정렬할 수 있어야 한다. | Must |
| FR-RET-005 | 반도체 약어, 영문명, 한글명을 이용해 질의를 확장해야 한다. | Must |
| FR-RET-006 | 문서 ID, 문서 유형, 언어, 날짜 조건으로 검색 범위를 제한할 수 있어야 한다. | Should |
| FR-RET-007 | 검색 응답은 개별 단계의 점수와 순위를 디버깅 정보로 제공해야 한다. | Should |
| FR-RET-008 | 표 Chunk와 일반 텍스트 Chunk를 함께 검색할 수 있어야 한다. | Must |

### 6.3 Answer & Citation

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-ANS-001 | 답변은 제공된 Evidence만을 근거로 생성해야 한다. | Must |
| FR-ANS-002 | 검증 가능한 핵심 Claim마다 하나 이상의 Citation이 있어야 한다. | Must |
| FR-ANS-003 | Citation은 문서명, PDF 페이지, Evidence 발췌를 포함해야 한다. | Must |
| FR-ANS-004 | 다중 문서 비교 시 정보의 출처 문서를 혼합하지 않아야 한다. | Must |
| FR-ANS-005 | 근거가 부족하면 `abstained=true`로 응답하고 이유를 제공해야 한다. | Must |
| FR-ANS-006 | 상충하는 근거가 있으면 차이를 숨기지 않고 문서별로 설명해야 한다. | Must |
| FR-ANS-007 | 설명 수준을 변경해도 Citation 집합은 유지되어야 한다. | Should |

### 6.4 Agent & MCP

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-AGT-001 | Agent는 질문 유형에 따라 필요한 MCP 도구를 선택해야 한다. | Must |
| FR-AGT-002 | 초기 검색 근거가 부족하면 제한된 횟수 안에서 질의를 재작성해야 한다. | Must |
| FR-AGT-003 | MCP 도구 오류 시 재시도 또는 안전한 답변 보류로 종료해야 한다. | Must |
| FR-AGT-004 | 각 MCP 도구는 Agent 없이 독립적으로 호출하고 테스트할 수 있어야 한다. | Must |
| FR-AGT-005 | Agent 실행은 노드, 도구 호출, latency, 종료 이유를 trace로 남겨야 한다. | Must |
| FR-AGT-006 | 최대 단계 수와 최대 재검색 횟수를 설정으로 제한해야 한다. | Must |

| NFR-001 | 재현성 | 동일 코드, 설정, 입력, 모델 버전으로 평가 결과를 재현할 수 있어야 한다. |
| NFR-002 | 추적성 | 답변에서 원본 문서의 실제 PDF 페이지까지 두 단계 이내로 접근할 수 있어야 한다. |

## 8. 답변 계약

```json
{
  "answer": "Vacuum Interlock은 챔버 압력이 허용 범위를 벗어날 때 발생합니다.",
  "abstained": false,
  "abstention_reason": null,
  "claims": [
    {
      "claim_id": "claim-1",
      "text": "Vacuum Interlock은 챔버 압력 이상과 관련된다.",
      "citation_ids": ["citation-1"]
    }
  ],
  "citations": [
    {
      "citation_id": "citation-1",
      "document_id": "doc-123",
      "document_title": "Equipment Manual",
      "page_number": 42,
      "quote": "Check chamber pressure and vacuum valve status.",
      "chunk_id": "chunk-123"
    }
  ],
  "trace_id": "trace-123"
}
```

`page_number`는 파일 내부 PDF의 실제 1-based 페이지다. 인쇄 페이지 번호가 별도로 존재하면 `printed_page_label`로 제공한다.

## 9. Acceptance Criteria

| ID | 검증 시나리오 | 통과 조건 |
| --- | --- | --- |
| AC-001 | 텍스트 PDF 등록 | 전체 페이지가 처리되고 각 Chunk의 `page_number`가 원문과 일치한다. |
| AC-002 | 스캔 PDF 등록 | 텍스트 부족 페이지가 OCR 처리되며 OCR 사용 여부가 기록된다. |
| AC-003 | 단일 문서 질문 | 정답 페이지가 Top-5에 포함되고 답변에 올바른 Citation이 있다. |
| AC-004 | 정확한 장비 코드 질문 | BM25 또는 Hybrid 결과가 코드가 포함된 페이지를 반환한다. |
| AC-005 | 다중 문서 비교 | 비교 항목마다 출처 문서와 페이지가 구분된다. |
| AC-006 | 표 기반 질문 | 답변 값이 올바른 행·열 관계와 페이지를 참조한다. |
| AC-007 | 답변 불가능 질문 | 시스템이 근거를 생성하지 않고 답변을 보류한다. |
| AC-008 | 상충 문서 질문 | 충돌 사실과 각 문서의 근거를 함께 반환한다. |
| AC-009 | 검색 도구 오류 | 정해진 재시도 후 구조화된 오류 또는 답변 보류로 종료한다. |
| AC-010 | 재현성 | 고정 평가 데이터와 설정으로 지표 계산을 다시 실행할 수 있다. |
