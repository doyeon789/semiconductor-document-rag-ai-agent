# Requirements Specification

## 1. 제품 목표

KISA·NIST·OWASP의 공개 AI 보안·위험관리 PDF를 검색하고, 사용자가 검증할 수 있는 **문서명·물리 페이지·원문 인용**을 포함해 답변합니다. 근거가 부족하면 추측 대신 답변을 보류합니다.

## 2. 대상 사용자와 질문

| 사용자 | 대표 질문 |
| --- | --- |
| AI 서비스 개발자 | 프롬프트 인젝션 위험과 권고 통제는 무엇인가? |
| 보안 담당자 | 레드티밍 절차와 위협 대응 항목을 어떤 순서로 확인해야 하는가? |
| 위험관리 담당자 | NIST AI RMF와 국내 가이드의 공통·차이점은 무엇인가? |
| 학습자·취업 준비생 | 특정 AI 보안 용어를 공식 문서 근거와 함께 설명해 달라. |

## 3. 범위

### 현재 구현

- 로컬 PDF 한 개의 네이티브 텍스트와 물리 페이지 추출
- 페이지 단위 Chunk와 안정적인 식별자 생성
- BM25, 다국어 Dense, RRF Hybrid, Cross-Encoder Rerank
- 검색된 원문 문장으로 구성한 추출형 답변
- 문서명·페이지·원문 발췌 Citation 검증
- 근거 부족 시 구조화된 답변 보류
- LangGraph 기반 제한된 재검색과 실행 trace
- FastAPI, Streamlit, 자동 평가 스크립트

### 다음 구현

- 출처 매니페스트의 6개 문서를 동시에 파싱·인덱싱
- 문서별 출처·언어·버전·제외 페이지 metadata 연결
- 기관 간 비교 질문과 답변 불가능 질문을 포함한 AI 보안 평가셋
- 새 코퍼스 기준 검색·Citation·답변 보류 threshold 재보정

### 현재 제외

- 사용자 PDF 업로드와 문서 관리 UI
- 스캔 문서 OCR과 복잡한 표 구조 복원
- 외부 LLM 기반 자유 생성 답변
- MCP 서버와 분산 검색 인프라
- 기업용 인증·권한·멀티테넌시
- 문서에 포함된 명령·URL·코드의 실행

## 4. 기능 요구사항

### 4.1 코퍼스와 문서 처리

| ID | 요구사항 | 상태 |
| --- | --- | --- |
| FR-COR-001 | 각 문서는 공식 landing page와 download URL을 가져야 한다. | 완료 |
| FR-COR-002 | 다운로드 파일의 PDF 서명과 SHA-256을 검증해야 한다. | 완료 |
| FR-COR-003 | 원본 PDF와 다운로드 영수증은 Git에서 제외해야 한다. | 완료 |
| FR-COR-004 | 문서별 제외 페이지는 1-based 번호로 기록해야 한다. | 완료 |
| FR-ING-001 | 모든 Chunk는 원본 문서 버전과 PDF 페이지로 역추적되어야 한다. | 단일 문서 완료 |
| FR-ING-002 | 6개 문서를 한 인덱스에서 구분해 검색할 수 있어야 한다. | 다음 |
| FR-ING-003 | 페이지 번호는 PDF의 1-based 물리 페이지를 사용해야 한다. | 완료 |
| FR-ING-004 | 텍스트가 없는 제외 페이지는 검색 인덱스에 넣지 않아야 한다. | 다음 |

### 4.2 검색

| ID | 요구사항 | 상태 |
| --- | --- | --- |
| FR-RET-001 | BM25와 Dense 검색을 각각 실행할 수 있어야 한다. | 완료 |
| FR-RET-002 | 두 결과를 RRF로 결합할 수 있어야 한다. | 완료 |
| FR-RET-003 | Hybrid 후보를 다국어 Cross-Encoder로 재정렬할 수 있어야 한다. | 완료 |
| FR-RET-004 | 검색 결과에 문서 ID, 버전 ID, 페이지와 점수를 포함해야 한다. | 단일 문서 완료 |
| FR-RET-005 | 한국어 질문으로 영어 문서를, 영어 질문으로 한국어 문서를 찾는 사례를 평가해야 한다. | 다음 |
| FR-RET-006 | 기관·언어·문서 ID로 검색 범위를 제한할 수 있어야 한다. | 다음 |

### 4.3 답변과 Citation

| ID | 요구사항 | 상태 |
| --- | --- | --- |
| FR-ANS-001 | 답변은 선택된 Evidence 원문만 사용해야 한다. | 완료 |
| FR-ANS-002 | 모든 Claim은 하나 이상의 검증된 Citation을 가져야 한다. | 완료 |
| FR-ANS-003 | Citation은 문서명, 버전, PDF 페이지와 원문 발췌를 포함해야 한다. | 완료 |
| FR-ANS-004 | 근거가 부족하면 `abstained=true`로 종료해야 한다. | 완료 |
| FR-ANS-005 | 비교 답변에서 기관별 주장을 서로 다른 Citation으로 구분해야 한다. | 다음 |
| FR-ANS-006 | Citation의 인용문은 해당 Evidence에 실제 포함되어야 한다. | 완료 |

## 5. 비기능 요구사항

| ID | 영역 | 요구사항 |
| --- | --- | --- |
| NFR-001 | 재현성 | 코퍼스 해시, 모델명, 설정과 Git SHA를 평가 결과에 기록합니다. |
| NFR-002 | 추적성 | 답변에서 실제 PDF 페이지까지 바로 이동할 수 있어야 합니다. |
| NFR-003 | 안전성 | API 키, 외부 PDF, 모델 cache와 생성 인덱스를 커밋하지 않습니다. |
| NFR-004 | 결정성 | 핵심 로직은 외부 LLM 없이 자동 테스트할 수 있어야 합니다. |
| NFR-005 | 성능 | 로컬 warm 검색 p95 2초 이하를 목표로 하며 모델 준비 시간은 별도 측정합니다. |
| NFR-006 | 정직성 | 현재 구현과 계획을 문서에서 명확히 구분합니다. |

## 6. Acceptance Criteria

| ID | 검증 시나리오 | 통과 조건 |
| --- | --- | --- |
| AC-001 | 코퍼스 다운로드 | 6개 파일이 매니페스트 SHA-256과 일치합니다. |
| AC-002 | 다중 문서 수집 | 773쪽에서 문서별 제외 페이지를 빼고 Chunk를 만들며 출처가 섞이지 않습니다. |
| AC-003 | 단일 문서 질문 | 정답 문서·페이지가 Top-5에 포함됩니다. |
| AC-004 | 기관 간 비교 | 각 비교 Claim이 올바른 기관 문서와 페이지를 인용합니다. |
| AC-005 | 한영 교차 검색 | 한국어·영어 교차 질문 slice의 Page Hit@5가 기준을 통과합니다. |
| AC-006 | 답변 불가능 질문 | 근거 없는 Claim과 Citation 없이 답변을 보류합니다. |
| AC-007 | Citation 검증 | 인용문이 지정한 문서 버전과 페이지 Evidence에 존재합니다. |
| AC-008 | 회귀 검증 | 테스트·Ruff·mypy·평가 스크립트를 같은 명령으로 다시 실행할 수 있습니다. |

## 7. 미확정 사항

- AI 보안 평가 질문의 최종 규모와 holdout 문서 분할
- 한국어↔영어 검색에 가장 적합한 embedding·reranker 조합
- 이미지 기반 표와 목차가 실제 질문 정답에 필요할 때의 OCR 범위
- KISA 원문을 외부 데모에서 직접 노출할 수 있는 재배포 조건
